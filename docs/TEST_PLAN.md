# MUARÉ — Test Plan MVP

Дата: 12.08.2026

## P0 — выпуск блокируется при ошибке

1. Публичная заявка создаётся без регистрации со статусом `PENDING`.
2. `PENDING` и `CONFIRMED` исчезают из свободных слотов и блокируют пересечения.
3. Два параллельных запроса на один слот создают только одну запись.
4. Цена, длительность, окончание и технический перерыв рассчитываются сервером.
5. Администратор подтверждает, отменяет и атомарно переносит запись.
6. При неудачном переносе исходное время не изменяется.
7. Мастер видит только свои записи и не может изменить чужую.
8. Публичный пользователь не получает клиентские данные, внутренние комментарии или причины занятости.
9. Прямой доступ без сессии к `/admin`, `/staff` и защищённым API отклоняется.
10. Роли `CUSTOMER`, маршрута `/my-bookings` и автоматического подтверждения нет.

## P1 — обязательно проверить до production

1. Запись через услугу и со страницы конкретного мастера.
2. Графики 2/2, противоположные смены, Пн–Пт и исключения.
3. Шаг 15 минут, технический перерыв 15 минут, горизонт и минимальное время.
4. Услуги на 60, 90 и 180 минут полностью помещаются в смену.
5. Очередь `PENDING`, общее расписание, ручная запись и список клиентов.
6. Статусы мастера `COMPLETED` и `NO_SHOW`.
7. Повтор запроса с тем же Idempotency-Key не создаёт дубликат.
8. Неверные UUID, телефоны, даты, статусы и слишком большой запрос возвращают контролируемую ошибку.
9. Вход ограничивает частые попытки; публичная заявка ограничивает частоту запросов.
10. Keyboard-only, видимый focus, ширина 360 px, tablet и desktop.

## Автоматические команды

```bash
npm run lint
npm run typecheck
npm run test
npm run format:check
npm run build
npm audit --omit=dev
```

Интеграционный concurrency-тест запускается только на отдельной test DB через
`BOOKING_TEST_BASE_URL`. Development и production данные для него не используются.

## Результат проверки

Для каждого запуска фиксируются дата, commit, окружение, выполненные P0/P1, найденные
ошибки и решение о выпуске. Непройденный P0 запрещает release.
