# Тестирование заявки

1. Сформировать сценарии из `spec.md`, `PLAN.md`, UX и API; при конфликте остановиться.
2. Подготовить изолированную test DB без изменения development и production данных.
3. Проверить выдачу доступных слотов, контакты и создание ожидаемой записи.
4. Проверить административную обработку и видимость записи мастеру.
5. Проверить отмену, перенос, освобождение времени и историю.
6. Проверить повторную отправку, два параллельных запроса и пересечения.
7. Проверить подмену цены, длительности, статуса, роли, мастера и организации.
8. Проверить одиночные услуги, комбинированный визит, технический перерыв, графики,
   исключения и границы времени.
9. Сверить UI, API и фактические строки БД.
10. Не считать мок бизнес-сервиса доказательством транзакционной защиты.
