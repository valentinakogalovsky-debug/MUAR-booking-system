# Проверка бизнес-правил

1. Прочитать `spec.md`, затем релевантный этап `PLAN.md`.
2. Если документы конфликтуют, применить стоп-правило из `AGENTS.md`.
3. Найти связанные подробности в Business Rules, UX, API и Data Model.
4. Не использовать этот skill как отдельный список требований: продуктовые правила
   всегда читаются из `spec.md`.
5. Составить список затрагиваемых инвариантов до изменения кода.
6. Проверить правила на сервере, в транзакции, ограничениях БД и тестах соразмерно риску.
7. При новом продуктовом решении сначала синхронизировать `spec.md` и `PLAN.md`,
   затем связанные документы и только после этого код.
8. Если решение пользователя отсутствует, остановиться и сообщить противоречие.
