# Code review

1. Начать с цели задачи, `spec.md`, этапа `PLAN.md` и фактического diff.
2. При конфликте документов остановить ревью реализации и сообщить конфликт.
3. Приоритет: потеря данных, доступ, двойная бронь, неверные время/цена, регрессии.
4. Проверить серверную валидацию, границы ролей и соответствие спецификации.
5. Проверить MSK/UTC, транзакции, идемпотентность и ограничения PostgreSQL.
6. Проверить доступность UI и отсутствие лишних клиентских данных.
7. Выдать замечания по критичности с файлами и строками.
8. Если существенных замечаний нет, прямо указать остаточные риски.
