# API endpoint

1. Сверить требование со `spec.md`, `PLAN.md` и API Specification.
2. При конфликте `spec.md` и `PLAN.md` остановиться по правилу `AGENTS.md`.
3. Определить вход, выход, коды ошибок и права доступа.
4. Валидировать вход на сервере; идентичность сотрудника брать из сессии.
5. Не возвращать и не принимать лишние приватные и вычисляемые поля.
6. Цена, длительность, `endAt`, `occupiedUntil` и статус рассчитываются сервером.
7. Использовать идемпотентность для изменяющих операций.
8. Не раскрывать существование приватных данных через 403/404.
9. Добавить тесты успешного сценария, валидации, доступа и конфликта.
