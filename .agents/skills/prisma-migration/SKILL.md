# Prisma migration

1. Прочитать `spec.md`, `PLAN.md`, Data Model, schema и все миграции.
2. При конфликте `spec.md` и `PLAN.md` остановиться по правилу `AGENTS.md`.
3. Проверить существующие данные и влияние изменения.
4. Не редактировать применённые миграции и не выполнять reset.
5. Изменить `schema.prisma`, затем создать новую именованную миграцию.
6. Сохранять серверные и PostgreSQL-инварианты, определённые в `spec.md`.
7. Seed делать идемпотентным; не удалять рабочие данные.
8. Выполнить validate, generate, migrate status и проверку на тестовой БД.
9. Сообщить SQL, риски отката и влияние на production.
