# Commit и push

1. Убедиться, что пользователь прямо запросил commit или push.
2. Проверить ветку, remote, status и полный diff; не включать несвязанные изменения.
3. Проверить соответствие `spec.md` и `PLAN.md`; при конфликте остановиться.
4. Использовать `$run-project-checks`; не продолжать при критической ошибке.
5. Проверить отсутствие `.env`, секретов, дампов и временных файлов.
6. Сформировать точный commit message по фактическому изменению.
7. Не использовать force push, destructive reset или переписывание истории.
8. Отправить только согласованную ветку и подтвердить удалённый commit.
9. Сообщить hash, ветку, remote, проверки и известные риски.
